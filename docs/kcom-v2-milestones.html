KCOM v2 Milestones

The rebuild in six milestones to launch, then three after. Each ends with something you can see and check.

flowchart LR
  M0[M0 Foundations] --> M1[M1 Content migration]
  M0 --> M2[M2 API and login]
  M2 --> M3[M3 Admin]
  M0 --> M4[M4 Public site]
  M1 --> M4
  M1 --> M5[M5 Launch]
  M3 --> M5
  M4 --> M5
  M5 --> M6[M6 Daily delivery]
  M5 --> M7[M7 Online giving]
  M5 --> M8[M8 Later ideas]

M1 and M2 can run side by side after M0. M4 can start with sample data and switch to migrated content once M1 is done. Durations are rough, for one developer working part time with AI help.

M0

Foundations

~1 week

Everything the rest of the work stands on.

Deliverables
  • Monorepo: pnpm workspaces, Turborepo, shared lint, TypeScript and formatting
  • Empty apps: Astro site, Hono API, React + Vite admin
  • content package with the content model; db package with Drizzle and Neon
  • Brand tokens and the three button types with all states
Infrastructure
  • GitHub Actions: lint, tests, Cloud Run deploy (reusing the CGHSR workflow)
  • Staging on Cloud Run behind Cloudflare
  • Sentry, PostHog, uptime check, Neon usage alert
  • Nightly encrypted database backup
Done when: a "hello" page and API are live on staging, deployed automatically from the main branch, with errors showing in Sentry.
M1

Content migration

~1–2 weeks

Every capsule, post and page from the Drupal site, cleaned and in the new database.

Deliverables
  • Load the Drupal export and files locally (kept out of git)
  • Extract, transform and validate scripts in packages/migrate
  • Capsules split into scripture, body, decrees, prayer; series detected
  • Embedded images moved to Cloudinary
Checks
  • Report of items that didn't parse cleanly
  • Manual review of ~50 sample capsules plus every flagged item
  • Real capsule count and oldest date confirmed
  • Redirect map from every old address to its new one
Done when: the import runs end to end, can be re-run safely, and the review sample reads correctly.
M2

API and login

~1–2 weeks

The Hono API the site and admin both use.

Deliverables
  • Endpoints for capsules, series, blog, pages and sections, books, gallery, settings
  • Drafts, scheduling and publishing
  • Image uploads to Cloudinary
  • Subscriber signup with double opt-in, Turnstile and unsubscribe
Login and permissions
  • Better Auth inside the API
  • Permission-based roles: Admin and Editor
  • Tests for permission checks
  • Publishing triggers a site rebuild
Done when: an editor can log in and create, schedule and publish a capsule through the API, and an editor is blocked from admin-only actions.
M3

Admin

~2–3 weeks

The staff editing app.

Content
  • Capsule editor with scripture, body, decrees, prayer and series fields
  • Calendar of scheduled capsules
  • Blog, books, gallery and page editors
  • Homepage and pages built from sections that can be reordered
Management
  • Users and roles
  • Subscribers list and CSV export
  • Site settings (giving details, social links)
  • Admin search (debounced), Motion for React animation
Done when: staff can run the site day to day without a developer.
M4

Public site

~3 weeks

The new kingdomcapstone.org in the Still Waters brand.

Pages
  • Homepage from sections; today's capsule; capsule page
  • Archive by month and by series; blog
  • About pages, Ministry Team, Books, Gallery, Partnership, Contact
  • Email signup form; privacy policy
Quality
  • Pagefind search, debounced
  • View transitions and Motion effects, reduced-motion respected
  • Dark mode, accessibility (WCAG AA), fast pages on phones
  • SEO: metadata, sitemap.xml, RSS, sharing images
Done when: the full site runs on staging with migrated content and passes accessibility and speed checks.
M5

Launch

~1 week

Switch over without losing links or content.

Before
  • Full QA across browsers and phones
  • Redirects tested against old addresses
  • Editor training and a short how-to guide
  • WhatsApp Channel and Telegram channel set up
Switch and after
  • Pause posting on the old site, final content sync
  • Move DNS to Cloudflare, go live
  • Watch 404s and errors for two weeks, add missing redirects
  • Submit sitemap to Google; keep the old site's export archived
Done when: kingdomcapstone.org serves the new site, old links redirect, and staff are publishing daily.
After the first release
M6

Daily delivery

  • Automated daily capsule email to confirmed subscribers (service chosen then)
  • Automatic Telegram post on publish
  • Optional weekly digest; WhatsApp Business API only if needed
M7

Online giving

  • Paystack one-off and monthly giving, reusing the CGHSR setup
  • Gold Give button; gifts recorded in the admin
  • Ministry's Paystack account and verification set up first
M8

Later ideas

  • Simplified flat logo
  • Audio versions of capsules
  • Contributor role for guest writers
  • Topics and tags for capsules
