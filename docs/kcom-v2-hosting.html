KCOM App Hosting

Where the three apps run: the Astro public site, the Hono API and the React admin. The database stays on Neon and images on Cloudinary.

What each app needs

  • Public site (Astro): mostly pre-built pages served from a CDN; a few server-rendered routes (today's capsule, search).
  • API (Hono): a small server or serverless functions that talk to Neon. Light traffic, mostly from the admin.
  • Admin (React + Vite): plain static files; any static host works.

Option: Google Cloud Run, as on the CGHSR site

The CGHSR site already runs on Cloud Run: a Docker image built and deployed by a GitHub Actions workflow, with Sentry, PostHog, Better Auth, Cloudinary and Drizzle. Most of that pipeline can be reused here.

Updated recommendation: Cloudflare in front, Cloud Run for the API.
  • Cloudflare (free): DNS for the domain, the pre-built Astro site, and the admin's static files. Unlimited bandwidth and a global CDN, so visitors never wait on a cold start.
  • Cloud Run (free tier): the Hono API in a Docker container, deployed the same way as CGHSR. Full Node removes the Workers compatibility checks.
  • Monitoring: reuse Sentry and PostHog from CGHSR.

The only visible cost is the API cold start, which the admin sees after idle periods. Public pages are unaffected because they're served from Cloudflare. Astro's few server-rendered routes (today's capsule, search) can be pre-built on a schedule or call the API.

Earlier recommendation: Cloudflare for all three apps.

One account for the site, API and admin. The free plan likely covers this site, with $5 a month as the upgrade. Hono runs natively on Workers, Astro has an official Cloudflare adapter, and serverless requests let Neon sleep between visits, which protects the 100 compute-hour allowance. Cloudflare also handles DNS, so the domain can move there too.

The one thing to check during setup: Workers run a trimmed-down runtime, so Better Auth and the Postgres driver need to be confirmed working there. Both are known to support it.
